# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Evidence-grounded, human-reviewed research workflow that collects a standardized 32-field water-source dataset per city. Core principle: **the AI is not the source** — every accepted value must trace back to evidence (utility, government, technical, regulatory, academic, or other approved source).

This is an early scaffold with one working vertical slice: `discover` → `acquire` (safe direct HTTP for HTML + pypdfium2 PDF text, raw files in MinIO) → context manager → VT extraction → validate (deterministic normalization) → resolve (deterministic acceptance/conflict rules) → review (interrupt/resume) → assemble (SupplyRecords, derived fields, quality checks) → finalize, persisted per run in Postgres, with standardized CSV/XLSX + provenance export. Apify and Computer Use acquirers raise `NotImplementedError`; Firecrawl is not wired into acquisition (only an external MCP tool exists); PDFs are text-layer only (no Docling tables/OCR); the per-city token/credit budgets are defined but not enforced; SupplyRecords persist as run snapshots (`supply_records`/`record_values`, 0008) but the full entity set in `docs/ER_MODEL.md` (separate source/utility/system tables) does not exist yet. Earlier runs are brought through the new stages by reprocessing (below).

## Architecture

**City runs are asynchronous (`research_queue/`)**: `POST /research/city` enqueues and returns 202 + `run_id` (200 with the existing run if that city — normalized city|country — is already QUEUED/RUNNING/AWAITING_REVIEW; enforced by a partial unique index). Clients poll `GET /research/runs/{run_id}` and fetch `/result`; `POST …/cancel`; `GET /research/queue/stats`. Workers (`ResearchWorker`, any number of processes/hosts) claim jobs from the `research_jobs` table with `SELECT … FOR UPDATE SKIP LOCKED` + a time-limited lease, run at most `worker_concurrency` graphs each (optional `max_running_global` cap via Postgres advisory lock), heartbeat to extend the lease, and retry failures with exponential backoff up to `max_attempts`. All state changes after claim are fenced by `lease_owner`, so a stalled worker that lost its lease can't overwrite anything. The graph is compiled with a checkpointer (`research_queue/checkpointing.py`: `AsyncPostgresSaver` on Postgres, tables created by its own `setup()`, not Alembic; `InMemorySaver` otherwise) using thread_id = run_id: a retried run resumes from the last completed step, and a run that finished but wasn't recorded is just recorded. Checkpoints are deleted after success unless `keep_checkpoints`. On shutdown, in-flight runs get `shutdown_grace_seconds` and are then released without consuming an attempt. A run whose graph pauses on human review (LangGraph `interrupt`, detected by `worker.paused_round(snapshot)`) is parked with `queue.await_review` as AWAITING_REVIEW (no lease, partial result stored, checkpoint kept, `review_round` set) — not failed, not done; `queue.resume_review` (from the API) re-queues it with a fresh attempt budget and the next worker continues with `Command(resume={"round": n})`. A pause that was never recorded (crash) is re-parked, never resumed without decisions. Review needs a persistent checkpointer: with `InMemorySaver` a waiting run doesn't survive a restart. Lease times use the app clock (keep hosts NTP-synced). On Windows, psycopg async needs a selector loop — use `checkpointing.run_async`. Settings: `research_queue/config.py` (`RESEARCH_QUEUE__*`). Tests: `tests/queue_helpers.py` (`Clock`, `Probe` node instrumentation, `Crash` for simulated process death).

**Worker supervision and crash evidence (`observability/supervisor.py`, `termination.py`, `evidence.py`, `worker_events.py`, `research_queue/diagnostics.py`; tables `worker_instances`/`worker_events`, migration 0014)**: the supervisor is a separate Python process that starts the worker with the venv's python directly (on Windows that is a launcher whose child is the real interpreter: the worker's own pid comes from its heartbeat file, and kills take the whole tree; a Job Object kills the worker if the supervisor dies). The exit code comes from the OS (`Popen.wait`), so it is recorded even when the worker ran no cleanup. One supervisor per log dir (OS file lock; also refuses while a previously recorded worker pid+create_time lives). Graceful stop = `logs/stop/<instance>.stop` (the worker's `Monitor` polls it and drains), kill after `stop_grace_seconds`. Restarts back off exponentially, RESTART_FAILED after `max_failures` per `failure_window_seconds`. A stale heartbeat (> `heartbeat_stale_factor` × `sample_seconds`) is HEARTBEAT_MISSING with `process_alive`, never death (kill-on-stall is opt-in). Worker id = instance id = lease owner. `Monitor` (every `OBSERVABILITY__SAMPLE_SECONDS`) writes the atomically replaced heartbeat file `logs/heartbeats/<instance>.json` (pid, RSS/private/CPU/threads/uptime, commit ratio, active runs with stage/attempt/trace, in-flight LLM requests and fetches, checkpoint write bytes from `checkpointing.measure_checkpoint_writes`), a rotating `logs/resources/<instance>.jsonl` (5 MB × 5) and the `worker_instances` row. At exit the supervisor gathers facts (exit code + NTSTATUS hex, uptime, last heartbeat and sample, worker-log markers: the excepthook's `worker exiting on an uncaught exception: <Type>`, faulthandler, stop marker, MemoryError; system memory; Windows power and Resource-Exhaustion events), classifies them (`termination.classify`: CLEAN_SHUTDOWN, UNHANDLED_EXCEPTION, NATIVE_CRASH, CONNECTION_FAILURE, EXTERNAL_TERMINATION, HEARTBEAT_TIMEOUT, POSSIBLE/CONFIRMED_MEMORY_EXHAUSTION, UNKNOWN_TERMINATION; confidence CONFIRMED/PROBABLE/POSSIBLE/UNKNOWN; CONFIRMED memory needs an OS/runtime kill record, the process's own out-of-memory status, or a terminating MemoryError plus same-window corroboration; exit 127 is never memory) and stores facts, cause, confidence and rationale separately, plus JOB_INTERRUPTED per run it held (heartbeat + lease table, with last trace/span). Recovery is recorded by the worker: JOB_LEASE_EXPIRED / JOB_RECLAIMED (`Job.reclaimed_from`, read in `claim`), CHECKPOINT_RECOVERY_ATTEMPTED (resume after a crash/failure, not a review), JOB_RESUMED / JOB_RECOVERY_FAILED (also `reap_expired_runs` on the final attempt); `GET /research/runs/{id}/lifecycle`. Durability: every event goes first to the writer's own `logs/events/<writer>.jsonl` (fsync), then Postgres; `EventSync` (supervisor, every `event_sync_seconds`, at start/exit) inserts unsynced lines idempotently by `event_id` from byte offsets in the atomically replaced `sync-state.json`, survives outages, leaves a torn last line for later; files rotate at `events_max_mb` (unique names) and only fully synced closed files are pruned above `events_retain_mb` (EVENT_FILES_PRUNED). Worker logs beyond 200 are pruned except those listed in `logs/crash-evidence.json`. Settings: `observability/config.py` (`OBSERVABILITY__*`). Tests: `tests/test_worker_supervisor.py` (real processes via `tests/fixtures/fake_worker.py`), `tests/test_termination.py`, `tests/test_worker_recovery_events.py`, `tests/integration/test_worker_events_pg.py`.

**Tracing (`observability/otel.py`, `observability/tracing.py`; migration 0015)**: `configure_telemetry(role)` installs the single global TracerProvider (worker, API via `_instrument` + FastAPIInstrumentor, run_city/evaluate/replay scripts) only when `OBSERVABILITY__OTEL_ENABLED=true`; it never replaces an installed provider (tests). BatchSpanProcessor with a bounded queue (`span_queue_size`), export timeout, OTLP gRPC or a rotating JSON-lines file exporter (`trace_exporter=file`, for offline debugging and multi-process tests); `shutdown_telemetry()` flushes with a bound; worker log lines carry `[trace=… span=…]`. Sampler `research_sampler(ratio)`: a root with `research.trace_requested=True` is always sampled, else `sample_ratio`; children follow their local parent; a remote parent (HTTP `traceparent`) never decides, so external headers can't force sampling. Selection is only `POST /research/city {"trace": true}` / `…/reprocess?trace=true` / `run_city.py --trace` → `research_jobs.trace_requested`, and `research_queue.submit` then starts a new sampled root linked to the HTTP span; its W3C context is stored in `research_jobs.trace_context`. The worker's first execution continues that stored context as a *local* parent (marked `consumed`); retries, reclaims and resumes start a new root linked to the submit context and the previous attempt; a resume after a crash adds `research.recovery` (links to the interrupted span from the supervisor's JOB_INTERRUPTED event, attribute `crash_event_id`). A review resume starts `research.review_resume` and stores its context for the next execution. `run_traces` rows (run_id, kind RUN/RECOVERY/REVIEW_RESUME, trace/span id, sampled) are written when the span starts, so ids survive a killed process whose spans were never exported; `GET /research/runs/{id}/traces` (Jaeger links). Evaluation spans (`evaluation.run`, `evaluation.judge`) are found by `research.run_id` (evaluation writes no research tables). Spans: `research_queue.submit` → `research.run` → `graph.<node>` → `discovery.discover`/`discovery.rank_results`/`discovery.<provider>.http`, `acquisition.fetch_document` → `acquisition.parse_document`, `extraction.field` (field, round, reextraction, attempt) → `context.*` / `llm.extract` → `llm.call` → `llm.request` (one per HTTP attempt: attempt, status, error kind, retry-after). URLs in attributes are `safe_url` (scheme/host/path). A hard-killed worker's unflushed spans are lost by design: crash detection is the supervisor's job. A checkpoint with values but no pending step and no `finalized` (process killed before LangGraph persisted its first steps) is restarted from the input, not recorded as success. Live check: `scripts/observability_check.py`. Tests: `tests/test_tracing.py` (the `ratio` fixture swaps the test provider's sampler and clears its tracer cache), `tests/integration/test_trace_recovery_pg.py` (real processes: supervisor, hard kill, reclaim, resume; `tests/fixtures/trace_worker.py`).

**LLM observability (`llm/router.py`, `observability/llm_telemetry.py`, `observability/langfuse.py`)**: every model call goes through the router, so every provider gets the same telemetry. `llm.call` = one logical call: provider, model, task, prompt version, latency, attempts, `llm.retries`, `llm.repairs`, `llm.validation_failures`, error kind, HTTP status, tokens (`gen_ai.usage.*`, `langfuse.observation.usage_details`, `llm.cached_tokens` from `prompt_tokens_details`/`input_tokens_details`), and context from the `llm_context` ContextVar (`llm_call_context(...)`, set by the extract node and the judge: run_id → also `session.id`, field_key, discovery round, re-extraction, attempt, bundle id). A fresh invocation is `langfuse.observation.type=generation`; a cache hit is a plain span (`llm.invocation=false`, no usage); each HTTP attempt is an `llm.request` child span (type span; its tokens are `llm.request.*`, never double counted). Missing usage is UNKNOWN (`llm.usage_known=false`, no token attributes; `llm_call_log` keeps None and the extract NODE event adds `usage_unknown_calls`), never 0. Cost only from `config/llm_prices.yaml` (empty: VT has no price) → otherwise `llm.cost_known=false`. Privacy: by default spans carry ids/usage/versions/status and HMAC-SHA256 digests of prompt and response (`llm.prompt_hmac`/`llm.response_hmac`; key from `OBSERVABILITY__HASH_KEY` or `logs/.telemetry-key`, created with owner-only permissions, git-ignored); text only with `OBSERVABILITY__CAPTURE_LLM_CONTENT=truncated` (opt-in; redacted secrets/emails/URL queries, 2000 chars; may contain evidence passages). Langfuse (optional extra, SDK 5.x): `configure_telemetry` calls `configure_langfuse(provider, settings)` when `OBSERVABILITY__LANGFUSE_ENABLED=true` and `LANGFUSE_PUBLIC_KEY`/`LANGFUSE_SECRET_KEY` (`LANGFUSE_HOST`) are set — `Langfuse(tracer_provider=<ours>, should_export_span=…, mask_otel_spans=…, mask=…)` adds its processor to the one provider (no second provider; Jaeger and Langfuse share trace ids); the filter exports only `LANGFUSE_SPANS` (research.run/recovery → graph.extract → extraction.field → llm.extract → llm.call → llm.request, evaluation.run → evaluation.judge, procedure distiller), so every exported span's parent is exported too; `mask_spans` deletes non-allowlisted attributes and redacts secret-shaped values in the Langfuse copy. Langfuse can be enabled without Jaeger (provider with no OTLP exporter). Unreachable Langfuse: exports fail on the processor thread, never in a run. Tests: `tests/test_llm_observability.py` (the `langfuse_export` fixture attaches Langfuse's processor with an in-memory exporter and detaches it; tests use `OBSERVABILITY__HASH_KEY` from conftest).

**Monitoring data (`observability/monitoring.py`, `observability/usage.py`, `observability/health.py`, `api/monitoring.py`; migration 0016)**: computed on read from stored records, no metrics database. `provider_usage` is the API usage/cost ledger: one row per logical external call (LLM now; CRAWL/SEARCH reserved for Firecrawl etc.), written by the router's `_CallStats._ledger` through `UsageRecorder` (background thread, bounded queue — overflow dropped and counted, batched inserts, bounded flush at exit; `configure_usage(engine)` in the worker, API, evaluate and replay processes; `OBSERVABILITY__USAGE_LEDGER`); category from `llm_call_context(category=…)` or the task (extract → research, eval_judge → evaluation, distill → procedure); per-attempt error counts, retries, cache hit (requests 0), tokens/cost NULL = Unknown. A hard kill loses at most the last ~1 s of queued rows. Dashboards take API usage from the ledger only; runs from before it fall back to their extract NODE events (`events_usage`, labelled "events (extraction only)"); never both. `time_split`: active = Σ step durations; queue wait = first attempt start − created; review wait = gaps after an attempt that paused on human_review (plus now − pause while AWAITING_REVIEW); other wait = remaining gaps (retries, crashes). `run_detail` (stages, progress, pipeline counts from discovery_results/source_documents/evidence_chunks/field_claims.validation_outcome, extraction per field from events, LLM by field, errors, Jaeger/Langfuse links, worker events), `workers` (ALIVE/STALE/STOPPED/EXITED from worker_instances; STALE = heartbeat older than sample × stale factor), `crashes`, `recovery_timeline` (incident = crash + supervisor restart outcome + per interrupted run RESUMED / RECOVERY_FAILED / PENDING: a restarted worker is not a resumed run), `usage(group_by=provider_model|city|run|category)` (`cost_status` KNOWN/PARTIAL/UNKNOWN/NO_CALLS). `health.backends` probes collector/Jaeger/Langfuse (only when enabled; 30 s cache); workers publish span-export counts (`otel.CountingExporter`, `exporter_stats`) and ledger counters in their heartbeat sample. API `/monitoring/overview|runs|runs/{id}|workers|crashes|recovery|usage|backends|alerts`. Prices only from `config/llm_prices.yaml` (`prices`, `credit_prices`). Tests: `tests/test_usage_ledger.py`, `tests/test_monitoring.py`, `tests/integration/test_monitoring_pg.py`.

**Dashboard (`ui/`, Streamlit)**: talks only to the API via `ui/client.py::ResearchApiClient` (inject a fake via `st.session_state["client"]`; tests use `streamlit.testing.v1.AppTest`). City dropdown = `config/cities.yaml` (generated from the project workbook; `services/city_catalog.py`, `GET /research/cities`). Progress = `research_run_steps`: the worker streams the graph (`astream(stream_mode="updates")`) and records each completed node with a compact summary from `research_queue/steps.py::summarize_step` (`GET /research/runs/{id}/steps`). **Workflow (LangGraph, `agents/`)**: `plan → discover → acquire → extract`, then extract routes back to `discover` while `fields_needing_evidence` is non-empty and `discovery_rounds < MAX_DISCOVERY_ROUNDS_PER_CITY`, else `validate` → `resolve` → (`human_review` ⇄ `resolve` while any field needs a person) → `assemble` → `finalize`. State is the `GraphState` TypedDict (`agents/state.py`) and carries the run: `run_id`, serialized `research_state` (CityResearchState), `evidence_chunks`, `seen_evidence`; LangGraph drops keys not declared there. Nodes return `{**state, ...}`; `plan` fills in `run_id`/`research_state` if the caller didn't. `build_graph(gateway=, context_service=, max_discovery_rounds=, procedure_memory=, usage_tracker=, run_recorder=, capability_availability=)` injects dependencies; the default `UnconfiguredGateway` raises once a READY bundle reaches it. Nodes append **trusted workflow events** to `state["events"]` via `schemas/events.py::append_event` (allow-listed attrs, URLs stripped to scheme/host/path, secrets redacted); these are the only input to procedure distillation, so new nodes that call tools must emit `TOOL_CALL` events with a `Capability`. `human_review` → `resolve` loops until nothing is open (see Human review below); a reviewer's decisions are never recomputed by the rules.

**Validation and resolution (`services/normalization.py`, `services/resolution.py`; deterministic, no model calls)**: `validate` gives every claim a stable `claim_uid` (sha1 of field, extracted value, status and cited url/page/normalized quote), a `normalized_value`, `qualifiers` (reference year and its basis, reported value/unit, measurement basis, source types/dates) and a `ClaimValidation` (one `ValidationCheck` per code: TYPE/ENUM/RANGE, EVIDENCE_PRESENT, CITATION_LINKED (quote must occur in the run's chunks; "…" elisions and chunk boundaries handled by `EvidenceIndex.locate`), VALUE_IN_QUOTE (numbers and units re-parsed from the quote: m3/d, ML/d, MLD, MGD, litres, gallons, annual volumes ÷ 365/366/365.25 per the methodology), MEASUREMENT_BASIS, APPROXIMATE_VALUE, GEOGRAPHIC_SCOPE, REFERENCE_YEAR, DEPENDENCY, FORMAT, ...). Claims are never dropped: INVALID ones stay visible and are never selected. `resolve` groups equivalent claims per field and entity (`city`, a water-source key from `name_key`, `*` = every record, `unattributed`), treats different reference years as history (latest is current), lets `multi_valued` values and several water sources coexist, attributes source-level claims by the source name in the quote, then its sentence, then its chunk, and sets RESOLVED (rule `AUTO_STRICT`) only when one claim in the group is VALID except allow-listed warnings, has VALUE_IN_QUOTE and CITATION_LINKED PASS, and cites a source type in the field's `official_sources` (default UTILITY/GOVERNMENT/REGULATORY), and the field isn't `review_always`. Same-year disagreement → CONFLICT; everything else with candidates → HITL_REQUIRED with reason codes. Confidence never decides. Results live in `FieldState.resolution` (`FieldResolution` → `EntityResolution`s) and the append-only `resolution_log` (state) / `field_resolutions` table; events: one `VALIDATION` per claim, one `RESOLUTION` per changed (field, entity), `EVIDENCE_ACCEPTED`, `FIELD_TRANSITION` (`NON_PLANNING_KINDS` keeps VALIDATION/RESOLUTION out of distillation trajectories). Bump `NORMALIZATION_VERSION` / `RESOLUTION_POLICY_VERSION` (`core/versions.py`) when the checks or rules change. Tests: `tests/resolution_helpers.py` (`World` evidence, `claim`, `normalize`, `resolve`).

**Human review (`services/review.py`, `schemas/review.py`, `db/review_models.py`, `build_graph(review_store=ReviewRepository)`; production wires it whenever there is a checkpointer)**: `open_review_items` = one item per (field, entity) of the researched fields that the rules left CONFLICT/HITL_REQUIRED/UNRESOLVED, plus NO_EVIDENCE items for fields with nothing to resolve (derived and `generated` fields never). The node persists claims/resolutions (`save_results`) and the round's items (`review_items`, id = hash(run, round, field, entity), payload = exactly what the reviewer sees incl. validation and chunk-linked citations), then `interrupt({"round": n})`. On resume it re-runs from the top (idempotent), reads the latest decision per item from `review_decisions` (append-only; never the resume payload), applies them (`apply_decisions`), marks the items APPLIED, and routes to `resolve`; another round follows if anything is still open. Decisions (reasons optional; the server stores a plain `decision_basis`): APPROVE (SELECT = alias; only claims shown, one unless `multi_valued`; an INVALID claim only with `override_validation`, rule `REVIEW_APPROVE_OVERRIDE`; may name `rejected_claim_uids` when another value is picked), REJECT (claims kept with `review_status=REJECTED`, never selected; if no usable candidate is left the entity becomes NEEDS_RESEARCH, rule `REVIEW_REJECT` — not Unknown, no new review or research round; otherwise the rules re-resolve the rest), CORRECT (new claim with its own `claim_uid`, `corrected_from`; needs evidence: a verbatim quote from a run chunk, or a reviewer-supplied URL kept as `REVIEWER_SUPPLIED`), ASSIGN_SOURCE (`assigned_entity_key`; rules re-resolve), MARK_UNKNOWN / DEFER (→ UNAVAILABLE), MARK_NA. Applied decisions become `EntityResolution(decided_by="REVIEWER", review_decision_id=…)`, `field_resolutions` rows with `review_decision_id`, and HITL/EVIDENCE_ACCEPTED/FIELD_TRANSITION events. API: `GET …/review/pending`, `GET …/review/items/{id}` (adds cited chunk texts), `POST …/review/decisions` (422 invalid, 409 stale round/closed item/reused `decision_key`; idempotent per `decision_key`), `POST …/review/resume` (409 until every open item has a decision), `GET …/review/progress`, `GET …/review/history`; `/result` also serves the partial state of an AWAITING_REVIEW run. Without a review store (tests/scripts) the node applies inline field-level `review_decisions` (APPROVED/CORRECTED/REJECTED) via `legacy_decisions`. Evidence classes (`ClaimQualifiers.evidence_class`): MACHINE_VERIFIED (quote found in a run chunk; extraction or a correction quoting the run's evidence), REVIEWER_SUPPLIED (a reviewer URL/note: its CITATION_LINKED / VALUE_IN_QUOTE / SOURCE_TIER failures become 'not machine-verified' warnings — never INVALID, never independent verification), HUMAN_VERIFIED (an APPROVE override; the machine checks keep their result). `ReviewEvidence` may carry `reference_year` (kept as `year_basis = reviewer`; feeds the withdrawal-year derivation), `source_date`, `page_number`; the simple review UI asks for an optional reporting year; the provenance export has an `evidence_class` column. Reviewer identity is the typed `reviewer` (whitespace-normalized) plus `reviewer_key` (casefolded) on every decision; no auth. `review_decisions` (0011) also records `decision_basis`, `rejected_claim_uids`, `validation_override` and `status_after` (written once when applied). Tests: `tests/review_helpers.py` (`World`: queue + API + review graph), `tests/test_human_review.py`, `tests/test_review_service.py`, `tests/integration/test_human_review_pg.py`.

**SupplyRecords, derived fields and export (`services/supply_records.py`, `schemas/records.py`, `services/record_store.py`, `services/export.py`, `schemas/standardized.py`)**: `assemble` builds a `RecordSet`: one `SupplyRecord` per accepted `water_source` entity (key = hash(city, country, source key); a single "Unknown" row if none), utility per record (`*` entity or attributed), every record-scope value per source and every city-scope value **once** (scope CITY; repeated only at export, never summed). Each `RecordValue` carries status/origin/reference year, its `claim_uids`, reviewer `review_decision_ids`, or a `Calculation` (rule, formula, inputs with their claim uids). Missing values are explicit: N/A, UNAVAILABLE → "Unknown", NO_EVIDENCE (researched, nothing found), NOT_RESEARCHED (field subset), or open (CONFLICT/HITL_REQUIRED/UNRESOLVED/CANDIDATE → blocks). Derivations (methodology rule numbers in the code) only fill gaps: total-withdrawal year from its claim (quote/passage year, not publication year), past withdrawals from historical claims, source contribution (single source = total, method of the total; remainder allocated when exactly one source is unknown; the rules' 0 + method "Unknown" when a researched contribution can't be estimated — its percentage stays Unknown), contribution method/year, withdrawal % (3 decimals; not if years differ), population served (city pop × share, ESTIMATED), % of population (1 decimal), "None Reported" for seasonal uses marked Unknown, References (generated from citations, labelled with what each source provided; city identity/population sources excluded; not full APA — no authors). Quality checks: OPEN_FIELD, ONE_SOURCE_PER_ROW, SCHEMA (`StandardizedWaterSourceRow`: every cell typed, "Unknown" or "N/A"), PERCENT_CONSISTENT, CONTRIBUTIONS_WITHIN_TOTAL, ESTIMATE_EXPLAINED, CITED_URLS_IN_REFERENCES, NOT_RESEARCHED → `completion` = FINALIZED | FINALIZED_WITH_GAPS | INCOMPLETE (`research_jobs.completion`; job status stays SUCCEEDED). `finalize` replaces the run's `supply_records`/`record_values` snapshot (`build_graph(record_store=)`). Export (`GET …/export?format=csv|xlsx&kind=standardized|provenance&requested_by=`; 409 unless SUCCEEDED and not INCOMPLETE): the workbook's 32 columns in order (`COLUMNS`/`HEADERS`; the workbook's 6th header typo is replaced by "City Population (millions)"), one row per record, cells formatted per the rules (`format_cell`, by column not Python type); XLSX adds Provenance, Quality control and Review log sheets; every file is recorded in `research_exports` (sha256, rows, requester). `GET …/records` (rows, quality, completion, exports) and `GET …/records/{record_key}/trace?field_key=` (value → resolution history and reviewer decisions → claims → citations → chunk text → document; calculated values recurse into inputs). Dashboard: **Records & export** tab (rows, failed checks, Prepare/Download buttons — files are generated on request because each is audited, trace view). Tests: `tests/test_supply_records.py`, `tests/test_export.py`, `tests/test_standardized_schema.py`.

**Extraction path**: `extract` (built by `make_extract_node`) calls `ContextService.get_context(run_id=, field_key=, operation=EXTRACT, graph_state=)` per field concurrently. Bundle status: `NOT_NEEDED` → skip; `NO_SUFFICIENT_EVIDENCE` → field goes to `fields_needing_evidence`; `READY` → `LLMGateway.extract(bundle, run_id=, field_key=)` (Protocol in `llm/gateway.py`), claims become candidates and `bundle.consumed` is added to `seen_evidence`. A READY bundle that yields no claims is also sent back to discovery (its chunks are now seen, so they aren't re-sent). Re-entry retries `fields_needing_evidence` plus entity-defining fields (`REEXTRACT_FIELDS`: water_source, utility_name, reservoir_names) that already have candidates when **materially new relevant evidence** arrived (`ContextManager.new_relevant_evidence`: unseen chunks with TARGET locality that name a water body or match the field's terms — no score threshold, so weaker passages naming another legitimate source count); bounded to one per round and `MAX_REEXTRACTIONS_PER_FIELD` (2) per run (`state['reextractions']`), no model call when nothing qualifies; the NODE event carries `reextraction`, `new_chunks`, `discovery_round` and LLM usage; new claims are merged and carry `qualifiers.extraction_round`. OTel spans: `graph.extract` → `context.get_context` → `context.load_state`, `context.bundle_create` → (on cache miss) `context_manager.build` → `context.retrieval`/`ranking`/`dedupe`/`budgeting`. Tests capture spans with the `spans` fixture in `tests/conftest.py`.

**Field subset**: a run may research only some fields — `POST /research/city {"field_keys": [...]}` (validated by `services/field_state.py::select_fields`, 422 on unknown keys; stored in `research_jobs.field_keys`), `run_city.py --fields`, smoke `--fields`. The research state still holds all 32 fields; only `unresolved_fields` is narrowed.

**Run persistence (`db/evidence_models.py`, `services/evidence_store.py::EvidenceRepository`, `build_graph(evidence_store=)`)**: `discover` writes `discovery_results` (0013; every hit each provider returned: query, provider, position, URL, source type, retained; insert-or-skip, soft — a failure is logged, never fails the run); `acquire` writes `source_documents` (every attempted URL, incl. failures, with raw object key) and `evidence_chunks` (insert-or-skip, so retries/resumes don't duplicate); `finalize` upserts `field_claims` by `(run_id, claim_uid)` (never deleted; legacy rows with NULL `claim_uid` are left untouched) with their validation columns, writes `claim_citations` once per claim (each linked to the chunk whose text contains the quote), appends `field_resolutions` (insert-or-skip by seq) and replaces the `run_field_states` snapshot (with its `resolution` JSON) before soft post-processing. These writes are hard: a failure fails the run and the queue retries it. The worker and smoke test build everything via `agents/runtime.py::build_production_graph` (also `ContextService(store=ContextBundleStore)` and a `RunRecorder` that always records `research_runs`/`run_events`, enqueueing distillation jobs only with procedure memory enabled). Read via `GET /research/runs/{id}/evidence`, `…/evidence/chunks?document_id=`, `…/claims`; `…/fields` adds `researched`, `review_required` and per-citation `source_type`/`acquisition_method`/`source_date` (joined from `acquired_documents`).

**Reprocessing (`services/reprocess.py`, `POST /research/runs/{id}/reprocess`, `scripts/reprocess_run.py`)**: a REPROCESS job (`research_jobs.mode`, `parent_run_id`; only of a SUCCEEDED run, same city and field subset) gets its input from the parent: research state from the parent's job result (or rebuilt from its `field_claims`/`claim_citations`), and its `source_documents`/`evidence_chunks` copied into the new run (insert-or-skip; raw files are content-addressed and shared), so citations link and trace within the new run. `route_start` sends `state["reprocess_of"]` runs straight to `validate`; plan/discover/acquire/extract never run. The parent's rows are never modified.

**Operating a review (real data)**: start the API (`uvicorn …api.main:app`), a worker (`scripts/run_research_worker.py`) and the dashboard; a run that needs people shows 🧑‍⚖️ AWAITING_REVIEW → Review queue tab → set Reviewer in the sidebar → decide every item → "Submit decisions & resume" → the worker finalizes → Records & export tab (Prepare/Download, trace). Fields with `gap_filled_by` (city/country from the catalog; withdrawal year/history, contributions, population served from the derivations) are not review items when nothing was found.

**Field model — keep three places in sync**: the 32 fields are defined in `config/field_definitions.yaml` (key, `field_type` grouping used by procedural memory, subject `city`/`supply_record`, type, enum `allowed` values, `derived` flag, `depends_on`, `keywords` used for evidence ranking, and resolution hints `scope`, `unit`, `review_always`, `descriptive`, `official_sources`, `generated`, `gap_filled_by`; loaded as `FieldDefinition`s by `load_field_definitions`), mirrored by `schemas/standardized.py` (`COLUMNS` order/headers and `StandardizedWaterSourceRow`, the export row), and `tests/test_field_state.py` asserts the count is exactly 32. Derived fields (`percentage_total_population`, `source_withdrawal_percentage`) are computed in `services/supply_records.py` (with `services/rules_engine.py`), never extracted.

**Per-field resolution state (`schemas/`)**: each field has a `FieldState` with a `FieldResolutionStatus` (UNRESOLVED → CANDIDATE → CONFLICT / HITL_REQUIRED / RESOLVED, plus NOT_APPLICABLE, UNAVAILABLE = applicable but no reliable value, set only by an explicit decision, and NEEDS_RESEARCH = a reviewer rejected every candidate and chose nothing — exported as "Unknown" but kept as NEEDS_RESEARCH in provenance, the trace and the NEEDS_RESEARCH quality warning; `FINAL_STATUSES` in `schemas/common.py` = settled for this run). Candidates are `FieldClaim`s carrying `ValueStatus` (KNOWN/UNKNOWN/NOT_APPLICABLE), `ValueOrigin` (REPORTED/CALCULATED/ESTIMATED/ALLOCATED), confidence, and `EvidenceRef`s. A field counts as unresolved while UNRESOLVED, CONFLICT, or HITL_REQUIRED. On export, UNKNOWN → `"Unknown"` and NOT_APPLICABLE → `"N/A"` (`rules_engine.export_missing`).

**Domain model (`docs/ER_MODEL.md`)**: the central entity is `SupplyRecord` = one city receives water from one hydrologic source through one utility. Provenance chain: SourceDocument → artifact → EvidenceSpan → FieldClaim → FieldResolution → accepted data.

**Provider tiers** — adapters are small classes with a common async method:
- Discovery (`discovery/`, `async search(query, limit) -> list[SearchResult]`): SearXNG (web), OpenAlex + Semantic Scholar (academic), Crossref (`lookup_doi` verification/enrichment). Adapters share `discovery/http.py::ProviderHttpClient` (timeouts, per-provider concurrency + min-interval throttle, retries with jittered exponential backoff honouring `Retry-After`, in-process TTL/LRU cache whose key excludes `secret_params`) and raise typed `ProviderError`s. `discovery/service.py::DiscoveryService` runs web and academic queries concurrently, isolates each (provider, query) call, merges/ranks (`discovery/ranking.py`: dedupe by DOI → canonical URL → normalized title; score = `SOURCE_TYPE_WEIGHTS` tier × city/water relevance + a small rank-fusion term that can't cross tiers, so official sources stay first; tiers come from `discovery/normalize.py::classify_source_type` — a web result is UTILITY only if a utility name in its title is corroborated by its own host (sydneywater.com.au ~ "Sydney Water", cmwc ~ initials, amwater ~ "American Water"), or its host label names a utility (`thameswater`, `waternsw`) and the page isn't a blog/news/listicle; retail/service pages never are. Regression cases are real SearXNG results in `tests/test_discovery_ranking.py` — add new misclassifications there) and verifies top DOIs with Crossref. Queries come from `discovery/queries.py` (procedure `planned_queries` first, else per-field-type topics — water_source asks for rivers/springs/groundwater, not reservoirs; a `site:<utility host>` query for source/infrastructure/withdrawal/quality fields once a UTILITY document's host is known (`agents/nodes.py::utility_hosts`); one local-language topic per field type from `config/query_languages.yaml` for the city's country; queries already run, read back from TOOL_CALL events, aren't repeated). Acquisition takes candidates on a known utility host first. Directory/list/member pages and non-water corporate reports (annual/financial reports of companies outside the water sector) are not UTILITY/TECHNICAL (`_DIRECTORY_PATH`, `_non_water_corporate_report`). `build_graph(discovery=build_discovery_service(settings))` wires it in (the scripts do); without it `discover` is a no-op, which keeps tests offline. The node stores `discovery_candidates`/`candidate_urls`/`discovery_provider_status` and emits one TOOL_CALL per call (Crossref verification is one aggregate call with no query). Settings: `discovery/config.py` (`DISCOVERY__*`) + top-level `OPENALEX_API_KEY`, `SEMANTIC_SCHOLAR_API_KEY`, `CROSSREF_MAILTO`, `SEARXNG_URL`. Tests: `tests/discovery_helpers.py` (`Recorder` MockTransport handler, `Sleeps`, `FakeProvider`, `FakeCrossref`). Firecrawl/Apify discovery optional (not built).
- Acquisition (`acquisition/`): `AcquisitionService.acquire_round(candidates, previous_records)` (built by `build_acquisition_service(settings, artifact_store)`, injected as `build_graph(acquisition=)`; without it `acquire` is a no-op and only caller-supplied `evidence_chunks` exist — tests patch `graph_module.acquire_node`). Per round it picks ≤`max_documents_per_round` unattempted candidates (canonical URL), official tiers first (UTILITY > GOVERNMENT > REGULATORY > TECHNICAL > ACADEMIC > OTHER, discovery order within a tier, ≤`max_per_host`, run budget `max_documents_total`), fetches concurrently, isolates failures as records (`status` OK/EMPTY/FAILED/SKIPPED_DUPLICATE + `error_kind`), de-dupes by final URL and content SHA-256, and chunks with `services/evidence.py::chunk_document` (paragraph-aligned, verbatim spans, PDF per page with `page_number`, long paragraphs windowed, overlap, id = sha1(url|page|text)). Discovery snippets are never evidence. All network access goes through `safe_http.py::SafeFetcher`: http/https on 80/443 only, every host (each redirect hop) resolved and rejected if non-public (SSRF; DNS rebinding between check and connect is a known gap), manual bounded redirects, robots.txt per origin (5xx → host skipped), 401/403 → `AUTH_REQUIRED` (never bypassed), streamed size caps, per-host serialization + min interval and a global cap. HTML: `http.py` (`DirectHTTPAcquirer`, `parse_html`: trafilatura, BeautifulSoup fallback, date from trafilatura metadata); PDF: `pdf.py` (pypdfium2 text layer, no OCR; `acquisition_method=DIRECT_HTTP_PDF`). Raw bytes go to `artifacts.py::MinioArtifactStore` (content-addressed `sha256/xx/<hash>.<ext>`; upload failure keeps the evidence and records `artifact_error`). State: `acquired_documents` (records) + `evidence_chunks`; the node emits a `TOOL_CALL` per fetch (`static_document_fetch`/`direct_http`, plus `document_parsing`/`pdfium` for PDFs). Settings: `acquisition/config.py` (`ACQUISITION__*`, `ARTIFACTS__*`). Tests: `tests/acquisition_helpers.py` (`Site` MockTransport, fake `Resolver`, `make_pdf`, `MemoryArtifacts`), `tests/slice_helpers.py` (mocked Toronto world + scripted VT model). Firecrawl/Apify/Computer Use escalation is not wired yet.
- LLM routing (`llm/`): **every model call is built by `llm/router.py`** — never construct `OpenAI`/`AsyncOpenAI` clients elsewhere. `LLM_PROVIDER` (`vt` default | `openai`) selects exactly one backend; there is **no fallback** between providers (a VT failure must never reach paid OpenAI). Backends: `vt_client.py::VTChatBackend` (VT ARC, OpenAI-compatible Chat Completions via the `openai` SDK; `LLM__VT_STRUCTURED_MODE` = `json_schema`|`json_object`|`prompt`; VT API is reachable only on the VT Campus VPN — a plain-text 403 otherwise) and `openai_reasoner.py::OpenAIResponsesBackend` (Responses API `parse`; `OpenAIReasoner`/`OpenAIStructuredClient` kept). `build_structured_llm(settings, task=, prompt_version=, model=)` wraps the backend in `ReliableStructuredLLM` (`structured` sync / `astructured` async): process-wide `RateLimiter` (27 req/min + in-flight cap, thread- *and* event-loop-safe because distillation runs in `asyncio.to_thread`; per process — divide by worker count), in-process response cache keyed by provider/base URL/model/task/prompt version/schema hash/prompts, retries with jittered exponential backoff for 429/timeout/network/5xx only (honours `Retry-After` and VT's body `retry_after_s`), and client-side Pydantic validation of every response with bounded repair turns → `LLMError(SCHEMA)`. Errors are typed `llm/base.py::LLMError` (`LLMErrorKind`). Missing credentials for the *selected* provider raise `UNCONFIGURED` when a client is built; callers degrade (graph → `UnconfiguredGateway`, distiller → deterministic, embeddings → none). Policy: `llm/config.py::LLMSettings` (`LLM__*`). Current users: the extraction gateway, `LLMDistiller`, and procedure embeddings (`build_embedding_client`: VT `Qwen3-Embedding-4B` truncated+L2-normalised to `EMBEDDING_DIMENSIONS` (Matryoshka), queries get an `Instruct:` prefix; OpenAI `text-embedding-3-small`; vectors are only compared/merged within the same `embedding_model`, and switching models re-embeds via `embed_pending`). Tests: `tests/llm_helpers.py` (`Server` httpx2 MockTransport — the `openai` SDK runs on `httpx2`, not `httpx`; `vt_settings`/`openai_settings`; `make_llm`).
- Extraction gateway (`llm/extraction.py::StructuredExtractionGateway`, built by `build_extraction_gateway(settings)` in the scripts): implements `LLMGateway.extract`. Per call it builds a response schema (`create_model`, `extra="forbid"`) whose citations may only name the `S#` sources carrying evidence for the target field, typed by `FieldDefinition.type` (enum → `allowed` only, coordinates range-checked, KNOWN ⇒ value, NOT_APPLICABLE ⇒ null). Each citation's quote must occur (case/whitespace/Unicode-normalised) in the passage shown; ungrounded citations are dropped and claims left without one rejected; citations map to `EvidenceRef` via `bundle.evidence_ref(sid, passage=quote)`. `LLMError(SCHEMA)` → no claims (field returns to discovery/review); other `LLMError`s propagate so the research queue retries the run (successful fields are cache hits). Fields marked `multi_valued` in `config/field_definitions.yaml` (`water_source`, `reservoir_names`) get a prompt line asking for one claim per distinct value. Every prompt shows the field's methodology definition (`FieldDefinition.definition`, merged from `config/field_descriptions.yaml` by `load_field_definitions`). water_source / reservoir_names claims must state a `source_kind` (`schemas/research.py::SOURCE_KINDS`) and may carry `relations` (on_river, on_lake, fed_by, part_of_system, drawn_from), each grounded in its own verbatim quote (ungrounded ones dropped), stored in `qualifiers.source_kind/relations`. Bump `EXTRACTION_PROMPT_VERSION` (`core/versions.py`) when the prompt or schema changes.

**Context manager (`context_manager/` package: `manager.py` builds bundles, `store.py` persists them, `service.py` is the graph entry point; import from `water_source_research.context_manager`)**: every LLM call should get its prompt context from `ContextManager().build(ContextTask(purpose, target_fields), city_state, chunks, seen)` (the graph goes through `ContextService`). It is pure/in-memory. Per `ContextPurpose` it prunes targets (already-resolved, derived, nothing-to-resolve → `bundle.skipped_fields`; `bundle.is_empty` means skip the LLM call), adds resolved anchor/`depends_on` values as one-line facts, and then either ranks chunks (EXTRACT: keyword BM25 × source-type prior × locality × digit heuristics; locality is judged on the matching sentences ±1 — TARGET / MIXED / NONE / OTHER — using the target city/country and the other places in `config/gazetteer_cities.yaml` (the methodology's appendix city list, independent of the workbook), so multi-city report headers don't make another city's passage local; for water_source / reservoir_names a named water body (`HYDRONYM`) in a sentence about the city boosts the chunk and gets up to 3 extra seeds, one per document first; per-target seed pass, dedupe, a per-source cap relaxed to 2× only for TARGET chunks scoring ≥ half the best, sentence excerpting incl. hydronym sentences; the token budget is a ceiling, never filled for its own sake; RETRIEVAL_POLICY_VERSION 4) or lists candidate/selected claims (RESOLVE_CONFLICT / VALIDATE: all claims kept, passages shrunk). Sources get `S#` ids; `bundle.evidence_ref("S1")` maps an LLM citation back to an `EvidenceRef`. Callers persist `bundle.consumed` into `seen` so the same (chunk, field) isn't re-sent. The manager never calls a model; LLM response caching belongs in the LLM layer, keyed by `bundle.fingerprint`/`bundle_id`.

**Bundle persistence (`context_manager/store.py`, `db/`)**: `ContextBundleStore(engine).get_or_build(manager, task, state, chunks, seen)` (or `aget_or_build` from async nodes) reuses a stored bundle from the `context_bundles` table when `ContextManager.cache_key(...)` matches. The key covers the policy signature (`RETRIEVAL_POLICY_VERSION`, manager config, token estimator, field definitions) plus only the inputs the build reads: target/anchor/`depends_on` field states, and for EXTRACT the chunk contents and `seen` pairs for the targets. **Bump `RETRIEVAL_POLICY_VERSION` when changing scoring/excerpting/rendering logic** so old bundles aren't reused. Concurrency: a per-key in-process lock builds each bundle once, and the unique `cache_key` constraint settles races across processes (the loser returns the winner's row). `db/` is the repo's first DB code: `db/models.py` (SQLAlchemy 2.x declarative, JSON→JSONB on Postgres) and `db/session.py` (`get_engine()` from `DATABASE_URL`, `init_db()` = `create_all`, schema changes go through Alembic in `migrations/`; `init_db()` = `create_all` for tests/dev). Dialect-specific DDL (the pgvector HNSW index) is declared on the model with `.ddl_if(dialect="postgresql")`, and `db/models.py::include_object_for` keeps Alembic from reporting it as drift on other backends — SQLite-only checks can't catch Postgres drift, so `tests/integration` includes a Postgres drift test). Store tests run on a file-backed SQLite in `tmp_path`. OpenTelemetry (`observability/otel.py`) is intended as the canonical audit layer (run/city/field IDs, provider/model, tokens, latency, cost, confidence, HITL events).

**Evaluation (`evaluation/`, `api/evaluation.py`, `eval_*` tables, migration 0010)**: independent of the research pipeline — it only *reads* research tables (a test asserts their row counts are unchanged), makes no web calls, and its only model calls are the cached semantic judge (below). `reference.py` imports the manually researched workbook (or CSV) into a versioned dataset (id = hash of file + sheet + `REFERENCE_POLICY_VERSION`; raw values kept, normalization policies in `policy.py` emit issues such as HEADER_BY_POSITION, FRACTION_PERCENT, PLACEHOLDER; References column → source URLs per field via `REFERENCE_LABELS`). `snapshot.py::build_snapshot` freezes a run (REPROCESS runs follow `parent_run_id` for discovery/acquisition/extraction history) and defines the stages: RAW = claims as extracted (CORRECTED excluded; a cell scores its best candidate = "any-candidate recall", Advanced only), PROPOSED = the one value the system put forward per cell before any person (the AUTO value, else `evaluate.py::proposal_order`'s first candidate; every candidate kept with its own comparison, `candidate_count`, `selected_claim_uids`, `selection_reason`), AUTO = last RULES resolution before the first REVIEWER row, FINAL = record values with origin (RULES/REVIEWER/DERIVED/CATALOG/GAP; NEEDS_RESEARCH = no answer), only for finished runs. Cells (compare-6): a source-level field whose workbook value is the same in every row of a multi-source city is ONE city-wide cell (tag CITY_WIDE_IN_REFERENCE; no fan-out); record cells of a workbook source the run never identified are MISSING_PREDICTION (SOURCE_NOT_IDENTIFIED), never credited from city-wide claims. Sources pair one to one (`_pair`: name/alias, then judge EQUIVALENT as a provisional fallback) and `source_metrics` stores source_precision / source_recall per stage (matched, missing, extra, provisional). The judge refines RAW candidates as well (same question, same cached verdict as PROPOSED). A FINAL stage whose review decisions came from `reference_reviewers` (config/evaluation.yaml) is REFERENCE_DERIVED: labelled and never pooled. `scripts/review_from_reference.py` is read-only. Researcher scores (`metrics.py::simple_scores`, PROPOSED/AUTO/FINAL): comparable C (reference has a value, N/A or None reported), answered A, coverage A/C, accuracy strict MATCH/A and lenient (MATCH + 0.5 PARTIAL)/A, `provisional` = unverified judge results; `views.py` serves the side-by-side rows (`GET /evaluation/runs/{id}/comparison?stage=`, `/evaluation/cities`, `/evaluation/performance`; no cross-city average from fewer than two cities). `compare.py` is deterministic (tolerances/aliases in `config/evaluation.yaml`, `config/evaluation_aliases.yaml`, `COMPARE_POLICY_VERSION`); descriptive text is never an automatic MATCH; fields outside a run's `field_keys` subset with no output are NOT_RESEARCHED. Semantic judge (`judge.py`, `eval_judgments` 0012): only for cells the rules can't decide (descriptive fields; name fields that are neither identical nor aliased) — never numbers/years/categories/coordinates or hard-rule mismatches (TEMPORAL, SCOPE flags, N/A vs value); strict structured output (verdict, overlapping/missing/differing facts, measure/scope/period checks, justification) with deterministic caps (`map_verdict`), definitions from `config/field_descriptions.yaml` (kept apart from field_definitions.yaml so research caches don't change), cached by inputs + model + `JUDGE_PROMPT_VERSION`; unavailable/failing model → NEEDS_REVIEW (not cached). Judged cells keep `deterministic_status` and are provisional until adjudicated. It is NOT validated until the labels in `tests/evaluation/judge_cases_toronto.yaml` are confirmed by a person and `scripts/judge_calibration.py` passes (`views.JUDGE_VALIDATED` stays False until then). Tests never reach a real model (autouse fixture in `tests/conftest.py`). `evidence.py` checks citations against stored chunk text (a verified quote is not proof of the value). `diagnosis.py` finds the earliest demonstrable failure (with recorded `discovery_results` it tells "returned by a recorded search but ranked out" from "not returned in the recorded searches"; both stay PROBABLE — recorded searches never show a source was unavailable; order: evidence → discovery → acquisition → retrieval → extraction → resolution → review/derivation) with a probe trail; confidence CONFIRMED/PROBABLE/UNKNOWN, symptoms separate from root cause, and it never guesses (no labelled reference source → row-URL fallback with weaker conclusions). Volume rates come from `normalization.quantities` (`volume_rates`; since normalize-2 a filler such as "of drinking water" before the period keeps the unit). `metrics.py` stores every metric with numerator, denominator and exclusions (AUTO precision always carries its coverage). Each evaluation is a new `eval_runs` row (snapshot + sha256); adjudications (`eval_adjudications`, append-only) are separate from research review decisions. `report.py::effective` applies the latest adjudication per target on read (stored results never change; metrics are recomputed from the frozen snapshot, original status/root cause kept); the API serves that view and renders reports (`GET /evaluation/runs/{id}/report?kind=summary|fields|city|evidence|failures|metrics&format=md|json|csv`, `GET /evaluation/overview`). `manual.py` checks an evaluation against a manual-findings YAML (written independently of the evaluator; never edit it to match — disagreements are the output). Bump `COMPARE_POLICY_VERSION` when comparison logic changes (compare-2: descriptive fields are compared by concept before list handling; consistent stemming; compare-3: PROPOSED stage and researcher scores; compare-4: semantic judge). Known instrumentation gaps are recorded per run (`evaluate.py::INSTRUMENTATION_GAPS`). Tests: `tests/evaluation/` (`eval_helpers.py` workbook builder, `eval_world.py` persisted mocked run + matching reference).

**Procedural memory (`procedures/`)**: reusable *research strategies* learned from validated runs — advisory planning guidance only, never evidence, field state, or an LLM cache. Keep those boundaries: procedure text must never get an `S#` id or satisfy an evidence requirement (`ContextTask.procedure_hints` render only for PLAN/QUERY_GENERATION, in their own section).
- Read path: `graph.plan` → `ProcedureMemory.retrieve(RetrievalRequest)` once per field type with unaccepted fields → SQL metadata filter (ACTIVE, task/field type, water type, `min_workflow_version`, required capabilities) → cosine over survivors only (pgvector `<=>` on Postgres, Python on SQLite) → `RankingPolicy` (Wilson lower bound, EWMA recent success, recency, correction penalty) → ≤`max_results`. `retrieve` never raises (degraded → default strategy). `choose_strategy` drops capabilities not in `available_capabilities()`; `discover` renders query templates into `planned_queries`.
- Write path (async, soft): `finalize` → `RunRecorder` persists `research_runs`/`run_events` and enqueues `distillation_jobs` (key = hash(trajectory_id, `DISTILLER_VERSION`)) → `DistillationWorker`: build trajectory from events → `EligibilityPolicy` → distiller (`procedure_memory.distiller`: `LLMDistiller` by default — the model only picks from per-trajectory enums of observed capabilities/queries/source types and never sees city names, URLs or providers; runs on the configured `LLM_PROVIDER` via the router and falls back to `DeterministicDistiller` when that provider has no credentials) → schema + `check_grounding` + `check_safety` (no URLs/domains/secrets; queries must template to observed, generic-vocabulary searches) → `MergeEvaluator` (same `procedure_key` = metadata + capability plan; structural Jaccard required, embedding cosine only as an extra guard) → CANDIDATE → `LifecyclePolicy` (support runs/cities, correction rate; `require_human_approval` → AWAITING_APPROVAL, approve via `POST /procedures/versions/{id}/approve`).
- Concurrency/idempotency live in the DB: unique `procedure_key`, `(procedure_id, version)`, origin `distillation_key`, usage `(version, run, field)`; partial unique index = one ACTIVE version per procedure; conditional UPDATEs for job claims/transitions; SQL increments for stats. Recipes are immutable; versions change only status/stats/embedding.
- Usage: retrieved → selected → applied → outcome (once) in `procedure_usages`; only applied usages move success/failure stats.
- All thresholds are in `procedures/config.py::ProcedureMemorySettings` (`PROCEDURE_MEMORY__*` env, validated at startup; disabled by default). Version constants are in `core/versions.py`; capabilities (vendor-independent) in `core/capabilities.py`.
- The distiller's version is part of the job key, so `RunRecorder` must be built with the worker's `distiller.version` (`build_procedure_services` does this). Bump `LLM_DISTILLER_VERSION` when the prompt or draft schema changes.
- Tests: `tests/procedure_helpers.py` (FakeEmbedder, `seed_version`, `run_state` event builders); metrics via the `metric_points` fixture.
