# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Evidence-grounded, human-reviewed research workflow that collects a standardized 32-field water-source dataset per city. Core principle: **the AI is not the source** — every accepted value must trace back to evidence (utility, government, technical, regulatory, academic, or other approved source).

This is an early scaffold with one working vertical slice: `discover` → `acquire` (safe direct HTTP for HTML + pypdfium2 PDF text, raw files in MinIO) → context manager → VT extraction → validate (deterministic normalization) → resolve (deterministic acceptance/conflict rules) → review (interrupt/resume) → assemble (SupplyRecords, derived fields, quality checks) → finalize, persisted per run in Postgres, with standardized CSV/XLSX + provenance export. Apify and Computer Use acquirers raise `NotImplementedError`; Firecrawl is not wired into acquisition; the Docling adapter (tables/OCR) and the SupplyRecord-level models in `docs/ER_MODEL.md` do not exist yet. Reprocessing earlier runs (built before validation/review/records existed) is not built yet.

## Architecture

**City runs are asynchronous (`research_queue/`)**: `POST /research/city` enqueues and returns 202 + `run_id` (200 with the existing run if that city — normalized city|country — is already QUEUED/RUNNING/AWAITING_REVIEW; enforced by a partial unique index). Clients poll `GET /research/runs/{run_id}` and fetch `/result`; `POST …/cancel`; `GET /research/queue/stats`. Workers (`ResearchWorker`, any number of processes/hosts) claim jobs from the `research_jobs` table with `SELECT … FOR UPDATE SKIP LOCKED` + a time-limited lease, run at most `worker_concurrency` graphs each (optional `max_running_global` cap via Postgres advisory lock), heartbeat to extend the lease, and retry failures with exponential backoff up to `max_attempts`. All state changes after claim are fenced by `lease_owner`, so a stalled worker that lost its lease can't overwrite anything. The graph is compiled with a checkpointer (`research_queue/checkpointing.py`: `AsyncPostgresSaver` on Postgres, tables created by its own `setup()`, not Alembic; `InMemorySaver` otherwise) using thread_id = run_id: a retried run resumes from the last completed step, and a run that finished but wasn't recorded is just recorded. Checkpoints are deleted after success unless `keep_checkpoints`. On shutdown, in-flight runs get `shutdown_grace_seconds` and are then released without consuming an attempt. A run whose graph pauses on human review (LangGraph `interrupt`, detected by `worker.paused_round(snapshot)`) is parked with `queue.await_review` as AWAITING_REVIEW (no lease, partial result stored, checkpoint kept, `review_round` set) — not failed, not done; `queue.resume_review` (from the API) re-queues it with a fresh attempt budget and the next worker continues with `Command(resume={"round": n})`. A pause that was never recorded (crash) is re-parked, never resumed without decisions. Review needs a persistent checkpointer: with `InMemorySaver` a waiting run doesn't survive a restart. Lease times use the app clock (keep hosts NTP-synced). On Windows, psycopg async needs a selector loop — use `checkpointing.run_async`. Settings: `research_queue/config.py` (`RESEARCH_QUEUE__*`). Tests: `tests/queue_helpers.py` (`Clock`, `Probe` node instrumentation, `Crash` for simulated process death).

**Dashboard (`ui/`, Streamlit)**: talks only to the API via `ui/client.py::ResearchApiClient` (inject a fake via `st.session_state["client"]`; tests use `streamlit.testing.v1.AppTest`). City dropdown = `config/cities.yaml` (generated from the project workbook; `services/city_catalog.py`, `GET /research/cities`). Progress = `research_run_steps`: the worker streams the graph (`astream(stream_mode="updates")`) and records each completed node with a compact summary from `research_queue/steps.py::summarize_step` (`GET /research/runs/{id}/steps`). Human review log and field-aware provenance are derived from the stored run result + trusted events in `reporting/run_views.py` (`GET …/review`, `GET …/fields`); citations come only from claim `EvidenceRef`s. The dashboard polls with `st.fragment(run_every=…)` only while a run is QUEUED/RUNNING. The **Review queue** tab (AWAITING_REVIEW runs) shows each item's candidates side by side with validation results and quoted citations, a decision form per item (decision_key = hash of the form content, so double submits are idempotent), and "Submit decisions & resume"; the reviewer name comes from the sidebar.

**Workflow (LangGraph, `agents/`)**: `plan → discover → acquire → extract`, then extract routes back to `discover` while `fields_needing_evidence` is non-empty and `discovery_rounds < MAX_DISCOVERY_ROUNDS_PER_CITY`, else `validate` → `resolve` → (`human_review` ⇄ `resolve` while any field needs a person) → `assemble` → `finalize`. State is the `GraphState` TypedDict (`agents/state.py`) and carries the run: `run_id`, serialized `research_state` (CityResearchState), `evidence_chunks`, `seen_evidence`; LangGraph drops keys not declared there. Nodes return `{**state, ...}`; `plan` fills in `run_id`/`research_state` if the caller didn't. `build_graph(gateway=, context_service=, max_discovery_rounds=, procedure_memory=, usage_tracker=, run_recorder=, capability_availability=)` injects dependencies; the default `UnconfiguredGateway` raises once a READY bundle reaches it. Nodes append **trusted workflow events** to `state["events"]` via `schemas/events.py::append_event` (allow-listed attrs, URLs stripped to scheme/host/path, secrets redacted); these are the only input to procedure distillation, so new nodes that call tools must emit `TOOL_CALL` events with a `Capability`. `human_review` → `resolve` loops until nothing is open (see Human review below); a reviewer's decisions are never recomputed by the rules.

**Validation and resolution (`services/normalization.py`, `services/resolution.py`; deterministic, no model calls)**: `validate` gives every claim a stable `claim_uid` (sha1 of field, extracted value, status and cited url/page/normalized quote), a `normalized_value`, `qualifiers` (reference year and its basis, reported value/unit, measurement basis, source types/dates) and a `ClaimValidation` (one `ValidationCheck` per code: TYPE/ENUM/RANGE, EVIDENCE_PRESENT, CITATION_LINKED (quote must occur in the run's chunks; "…" elisions and chunk boundaries handled by `EvidenceIndex.locate`), VALUE_IN_QUOTE (numbers and units re-parsed from the quote: m3/d, ML/d, MLD, MGD, litres, gallons, annual volumes ÷ 365/366/365.25 per the methodology), MEASUREMENT_BASIS, APPROXIMATE_VALUE, GEOGRAPHIC_SCOPE, REFERENCE_YEAR, DEPENDENCY, FORMAT, ...). Claims are never dropped: INVALID ones stay visible and are never selected. `resolve` groups equivalent claims per field and entity (`city`, a water-source key from `name_key`, `*` = every record, `unattributed`), treats different reference years as history (latest is current), lets `multi_valued` values and several water sources coexist, attributes source-level claims by the source name in the quote, then its sentence, then its chunk, and sets RESOLVED (rule `AUTO_STRICT`) only when one claim in the group is VALID except allow-listed warnings, has VALUE_IN_QUOTE and CITATION_LINKED PASS, and cites a source type in the field's `official_sources` (default UTILITY/GOVERNMENT/REGULATORY), and the field isn't `review_always`. Same-year disagreement → CONFLICT; everything else with candidates → HITL_REQUIRED with reason codes. Confidence never decides. Results live in `FieldState.resolution` (`FieldResolution` → `EntityResolution`s) and the append-only `resolution_log` (state) / `field_resolutions` table; events: one `VALIDATION` per claim, one `RESOLUTION` per changed (field, entity), `EVIDENCE_ACCEPTED`, `FIELD_TRANSITION` (`NON_PLANNING_KINDS` keeps VALIDATION/RESOLUTION out of distillation trajectories). Bump `NORMALIZATION_VERSION` / `RESOLUTION_POLICY_VERSION` (`core/versions.py`) when the checks or rules change. Tests: `tests/resolution_helpers.py` (`World` evidence, `claim`, `normalize`, `resolve`).

**Human review (`services/review.py`, `schemas/review.py`, `db/review_models.py`, `build_graph(review_store=ReviewRepository)`; production wires it whenever there is a checkpointer)**: `open_review_items` = one item per (field, entity) of the researched fields that the rules left CONFLICT/HITL_REQUIRED/UNRESOLVED, plus NO_EVIDENCE / ALL_CLAIMS_REJECTED items for fields with nothing to resolve (derived and `generated` fields never). The node persists claims/resolutions (`save_results`) and the round's items (`review_items`, id = hash(run, round, field, entity), payload = exactly what the reviewer sees incl. validation and chunk-linked citations), then `interrupt({"round": n})`. On resume it re-runs from the top (idempotent), reads the latest decision per item from `review_decisions` (append-only; never the resume payload), applies them (`apply_decisions`), marks the items APPLIED, and routes to `resolve`; another round follows if anything is still open. Decisions: APPROVE (SELECT = alias; only claims shown, not INVALID, one unless `multi_valued`), REJECT (claims kept with `review_status=REJECTED`, never selected; rules re-resolve), CORRECT (new claim with its own `claim_uid`, `corrected_from`; needs a reason and evidence: a verbatim quote from a run chunk, or a reviewer-supplied URL kept as `REVIEWER_SUPPLIED`), ASSIGN_SOURCE (`assigned_entity_key`; rules re-resolve), MARK_UNKNOWN / DEFER (→ UNAVAILABLE), MARK_NA. Applied decisions become `EntityResolution(decided_by="REVIEWER", review_decision_id=…)`, `field_resolutions` rows with `review_decision_id`, and HITL/EVIDENCE_ACCEPTED/FIELD_TRANSITION events. API: `GET …/review/pending`, `GET …/review/items/{id}` (adds cited chunk texts), `POST …/review/decisions` (422 invalid, 409 stale round/closed item/reused `decision_key`; idempotent per `decision_key`), `POST …/review/resume` (409 until every open item has a decision), `GET …/review/history`; `/result` also serves the partial state of an AWAITING_REVIEW run. Without a review store (tests/scripts) the node applies inline field-level `review_decisions` (APPROVED/CORRECTED/REJECTED) via `legacy_decisions`. Reviewer identity is the free-text `reviewer` (no auth yet). Tests: `tests/review_helpers.py` (`World`: queue + API + review graph), `tests/test_human_review.py`, `tests/test_review_service.py`, `tests/integration/test_human_review_pg.py`.

**SupplyRecords, derived fields and export (`services/supply_records.py`, `schemas/records.py`, `services/record_store.py`, `services/export.py`, `schemas/standardized.py`)**: `assemble` builds a `RecordSet`: one `SupplyRecord` per accepted `water_source` entity (key = hash(city, country, source key); a single "Unknown" row if none), utility per record (`*` entity or attributed), every record-scope value per source and every city-scope value **once** (scope CITY; repeated only at export, never summed). Each `RecordValue` carries status/origin/reference year, its `claim_uids`, reviewer `review_decision_ids`, or a `Calculation` (rule, formula, inputs with their claim uids). Missing values are explicit: N/A, UNAVAILABLE → "Unknown", NO_EVIDENCE (researched, nothing found), NOT_RESEARCHED (field subset), or open (CONFLICT/HITL_REQUIRED/UNRESOLVED/CANDIDATE → blocks). Derivations (methodology rule numbers in the code) only fill gaps: total-withdrawal year from its claim (quote/passage year, not publication year), past withdrawals from historical claims, source contribution (single source = total, method of the total; remainder allocated when exactly one source is unknown; the rules' 0 + method "Unknown" when a researched contribution can't be estimated — its percentage stays Unknown), contribution method/year, withdrawal % (3 decimals; not if years differ), population served (city pop × share, ESTIMATED), % of population (1 decimal), "None Reported" for seasonal uses marked Unknown, References (generated from citations, labelled with what each source provided; city identity/population sources excluded; not full APA — no authors). Quality checks: OPEN_FIELD, ONE_SOURCE_PER_ROW, SCHEMA (`StandardizedWaterSourceRow`: every cell typed, "Unknown" or "N/A"), PERCENT_CONSISTENT, CONTRIBUTIONS_WITHIN_TOTAL, ESTIMATE_EXPLAINED, CITED_URLS_IN_REFERENCES, NOT_RESEARCHED → `completion` = FINALIZED | FINALIZED_WITH_GAPS | INCOMPLETE (`research_jobs.completion`; job status stays SUCCEEDED). `finalize` replaces the run's `supply_records`/`record_values` snapshot (`build_graph(record_store=)`). Export (`GET …/export?format=csv|xlsx&kind=standardized|provenance&requested_by=`; 409 unless SUCCEEDED and not INCOMPLETE): the workbook's 32 columns in order (`COLUMNS`/`HEADERS`; the workbook's 6th header typo is replaced by "City Population (millions)"), one row per record, cells formatted per the rules (`format_cell`, by column not Python type); XLSX adds Provenance, Quality control and Review log sheets; every file is recorded in `research_exports` (sha256, rows, requester). `GET …/records` (rows, quality, completion, exports) and `GET …/records/{record_key}/trace?field_key=` (value → resolution history and reviewer decisions → claims → citations → chunk text → document; calculated values recurse into inputs). Dashboard: **Records & export** tab (rows, failed checks, Prepare/Download buttons — files are generated on request because each is audited, trace view). Tests: `tests/test_supply_records.py`, `tests/test_export.py`, `tests/test_standardized_schema.py`.

**Extraction path**: `extract` (built by `make_extract_node`) calls `ContextService.get_context(run_id=, field_key=, operation=EXTRACT, graph_state=)` per field concurrently. Bundle status: `NOT_NEEDED` → skip; `NO_SUFFICIENT_EVIDENCE` → field goes to `fields_needing_evidence`; `READY` → `LLMGateway.extract(bundle, run_id=, field_key=)` (Protocol in `llm/gateway.py`), claims become candidates and `bundle.consumed` is added to `seen_evidence`. A READY bundle that yields no claims is also sent back to discovery (its chunks are now seen, so they aren't re-sent). Re-entry only retries `fields_needing_evidence`. OTel spans: `graph.extract` → `context.get_context` → `context.load_state`, `context.bundle_create` → (on cache miss) `context_manager.build` → `context.retrieval`/`ranking`/`dedupe`/`budgeting`. Tests capture spans with the `spans` fixture in `tests/conftest.py`.

**Field subset**: a run may research only some fields — `POST /research/city {"field_keys": [...]}` (validated by `services/field_state.py::select_fields`, 422 on unknown keys; stored in `research_jobs.field_keys`), `run_city.py --fields`, smoke `--fields`. The research state still holds all 32 fields; only `unresolved_fields` is narrowed.

**Run persistence (`db/evidence_models.py`, `services/evidence_store.py::EvidenceRepository`, `build_graph(evidence_store=)`)**: `acquire` writes `source_documents` (every attempted URL, incl. failures, with raw object key) and `evidence_chunks` (insert-or-skip, so retries/resumes don't duplicate); `finalize` upserts `field_claims` by `(run_id, claim_uid)` (never deleted; legacy rows with NULL `claim_uid` are left untouched) with their validation columns, writes `claim_citations` once per claim (each linked to the chunk whose text contains the quote), appends `field_resolutions` (insert-or-skip by seq) and replaces the `run_field_states` snapshot (with its `resolution` JSON) before soft post-processing. These writes are hard: a failure fails the run and the queue retries it. The worker and smoke test build everything via `agents/runtime.py::build_production_graph` (also `ContextService(store=ContextBundleStore)` and a `RunRecorder` that always records `research_runs`/`run_events`, enqueueing distillation jobs only with procedure memory enabled). Read via `GET /research/runs/{id}/evidence`, `…/evidence/chunks?document_id=`, `…/claims`; `…/fields` adds `researched`, `review_required` and per-citation `source_type`/`acquisition_method`/`source_date` (joined from `acquired_documents`).

**Field model — keep three places in sync**: the 32 fields are defined in `config/field_definitions.yaml` (key, `field_type` grouping used by procedural memory, subject `city`/`supply_record`, type, enum `allowed` values, `derived` flag, `depends_on`, `keywords` used for evidence ranking, and resolution hints `scope`, `unit`, `review_always`, `descriptive`, `official_sources`; loaded as `FieldDefinition`s by `load_field_definitions`), mirrored by `schemas/standardized.py` (`COLUMNS` order/headers and `StandardizedWaterSourceRow`, the export row), and `tests/test_field_state.py` asserts the count is exactly 32. Derived fields (`percentage_total_population`, `source_withdrawal_percentage`) are computed in `services/supply_records.py` (with `services/rules_engine.py`), never extracted.

**Per-field resolution state (`schemas/`)**: each field has a `FieldState` with a `FieldResolutionStatus` (UNRESOLVED → CANDIDATE → CONFLICT / HITL_REQUIRED / RESOLVED, plus NOT_APPLICABLE and UNAVAILABLE = applicable but no reliable value, set only by an explicit decision; `FINAL_STATUSES` in `schemas/common.py`). Candidates are `FieldClaim`s carrying `ValueStatus` (KNOWN/UNKNOWN/NOT_APPLICABLE), `ValueOrigin` (REPORTED/CALCULATED/ESTIMATED/ALLOCATED), confidence, and `EvidenceRef`s. A field counts as unresolved while UNRESOLVED, CONFLICT, or HITL_REQUIRED. On export, UNKNOWN → `"Unknown"` and NOT_APPLICABLE → `"N/A"` (`rules_engine.export_missing`).

**Domain model (`docs/ER_MODEL.md`)**: the central entity is `SupplyRecord` = one city receives water from one hydrologic source through one utility. Provenance chain: SourceDocument → artifact → EvidenceSpan → FieldClaim → FieldResolution → accepted data.

**Provider tiers** — adapters are small classes with a common async method:
- Discovery (`discovery/`, `async search(query, limit) -> list[SearchResult]`): SearXNG (web), OpenAlex + Semantic Scholar (academic), Crossref (`lookup_doi` verification/enrichment). Adapters share `discovery/http.py::ProviderHttpClient` (timeouts, per-provider concurrency + min-interval throttle, retries with jittered exponential backoff honouring `Retry-After`, in-process TTL/LRU cache whose key excludes `secret_params`) and raise typed `ProviderError`s. `discovery/service.py::DiscoveryService` runs web and academic queries concurrently, isolates each (provider, query) call, merges/ranks (`discovery/ranking.py`: dedupe by DOI → canonical URL → normalized title; score = `SOURCE_TYPE_WEIGHTS` tier × city/water relevance + a small rank-fusion term that can't cross tiers, so official sources stay first; tiers come from `discovery/normalize.py::classify_source_type` — a web result is UTILITY only if a utility name in its title is corroborated by its own host (sydneywater.com.au ~ "Sydney Water", cmwc ~ initials, amwater ~ "American Water"), or its host label names a utility (`thameswater`, `waternsw`) and the page isn't a blog/news/listicle; retail/service pages never are. Regression cases are real SearXNG results in `tests/test_discovery_ranking.py` — add new misclassifications there) and verifies top DOIs with Crossref. Queries come from `discovery/queries.py` (procedure `planned_queries` first, else per-field-type topics; queries already run, read back from TOOL_CALL events, aren't repeated). `build_graph(discovery=build_discovery_service(settings))` wires it in (the scripts do); without it `discover` is a no-op, which keeps tests offline. The node stores `discovery_candidates`/`candidate_urls`/`discovery_provider_status` and emits one TOOL_CALL per call (Crossref verification is one aggregate call with no query). Settings: `discovery/config.py` (`DISCOVERY__*`) + top-level `OPENALEX_API_KEY`, `SEMANTIC_SCHOLAR_API_KEY`, `CROSSREF_MAILTO`, `SEARXNG_URL`. Tests: `tests/discovery_helpers.py` (`Recorder` MockTransport handler, `Sleeps`, `FakeProvider`, `FakeCrossref`). Firecrawl/Apify discovery optional (not built).
- Acquisition (`acquisition/`): `AcquisitionService.acquire_round(candidates, previous_records)` (built by `build_acquisition_service(settings, artifact_store)`, injected as `build_graph(acquisition=)`; without it `acquire` is a no-op and only caller-supplied `evidence_chunks` exist — tests patch `graph_module.acquire_node`). Per round it picks ≤`max_documents_per_round` unattempted candidates (canonical URL), official tiers first (UTILITY > GOVERNMENT > REGULATORY > TECHNICAL > ACADEMIC > OTHER, discovery order within a tier, ≤`max_per_host`, run budget `max_documents_total`), fetches concurrently, isolates failures as records (`status` OK/EMPTY/FAILED/SKIPPED_DUPLICATE + `error_kind`), de-dupes by final URL and content SHA-256, and chunks with `services/evidence.py::chunk_document` (paragraph-aligned, verbatim spans, PDF per page with `page_number`, long paragraphs windowed, overlap, id = sha1(url|page|text)). Discovery snippets are never evidence. All network access goes through `safe_http.py::SafeFetcher`: http/https on 80/443 only, every host (each redirect hop) resolved and rejected if non-public (SSRF; DNS rebinding between check and connect is a known gap), manual bounded redirects, robots.txt per origin (5xx → host skipped), 401/403 → `AUTH_REQUIRED` (never bypassed), streamed size caps, per-host serialization + min interval and a global cap. HTML: `http.py` (`DirectHTTPAcquirer`, `parse_html`: trafilatura, BeautifulSoup fallback, date from trafilatura metadata); PDF: `pdf.py` (pypdfium2 text layer, no OCR; `acquisition_method=DIRECT_HTTP_PDF`). Raw bytes go to `artifacts.py::MinioArtifactStore` (content-addressed `sha256/xx/<hash>.<ext>`; upload failure keeps the evidence and records `artifact_error`). State: `acquired_documents` (records) + `evidence_chunks`; the node emits a `TOOL_CALL` per fetch (`static_document_fetch`/`direct_http`, plus `document_parsing`/`pdfium` for PDFs). Settings: `acquisition/config.py` (`ACQUISITION__*`, `ARTIFACTS__*`). Tests: `tests/acquisition_helpers.py` (`Site` MockTransport, fake `Resolver`, `make_pdf`, `MemoryArtifacts`), `tests/slice_helpers.py` (mocked Toronto world + scripted VT model). Firecrawl/Apify/Computer Use escalation is not wired yet.
- LLM routing (`llm/`): **every model call is built by `llm/router.py`** — never construct `OpenAI`/`AsyncOpenAI` clients elsewhere. `LLM_PROVIDER` (`vt` default | `openai`) selects exactly one backend; there is **no fallback** between providers (a VT failure must never reach paid OpenAI). Backends: `vt_client.py::VTChatBackend` (VT ARC, OpenAI-compatible Chat Completions via the `openai` SDK; `LLM__VT_STRUCTURED_MODE` = `json_schema`|`json_object`|`prompt`; VT API is reachable only on the VT Campus VPN — a plain-text 403 otherwise) and `openai_reasoner.py::OpenAIResponsesBackend` (Responses API `parse`; `OpenAIReasoner`/`OpenAIStructuredClient` kept). `build_structured_llm(settings, task=, prompt_version=, model=)` wraps the backend in `ReliableStructuredLLM` (`structured` sync / `astructured` async): process-wide `RateLimiter` (27 req/min + in-flight cap, thread- *and* event-loop-safe because distillation runs in `asyncio.to_thread`; per process — divide by worker count), in-process response cache keyed by provider/base URL/model/task/prompt version/schema hash/prompts, retries with jittered exponential backoff for 429/timeout/network/5xx only (honours `Retry-After` and VT's body `retry_after_s`), and client-side Pydantic validation of every response with bounded repair turns → `LLMError(SCHEMA)`. Errors are typed `llm/base.py::LLMError` (`LLMErrorKind`). Missing credentials for the *selected* provider raise `UNCONFIGURED` when a client is built; callers degrade (graph → `UnconfiguredGateway`, distiller → deterministic, embeddings → none). Policy: `llm/config.py::LLMSettings` (`LLM__*`). Current users: the extraction gateway, `LLMDistiller`, and procedure embeddings (`build_embedding_client`: VT `Qwen3-Embedding-4B` truncated+L2-normalised to `EMBEDDING_DIMENSIONS` (Matryoshka), queries get an `Instruct:` prefix; OpenAI `text-embedding-3-small`; vectors are only compared/merged within the same `embedding_model`, and switching models re-embeds via `embed_pending`). Query generation, ranking, classification and validation are deterministic and use no LLM. Tests: `tests/llm_helpers.py` (`Server` httpx2 MockTransport — the `openai` SDK runs on `httpx2`, not `httpx`; `vt_settings`/`openai_settings`; `make_llm`).
- Extraction gateway (`llm/extraction.py::StructuredExtractionGateway`, built by `build_extraction_gateway(settings)` in the scripts): implements `LLMGateway.extract`. Per call it builds a response schema (`create_model`, `extra="forbid"`) whose citations may only name the `S#` sources carrying evidence for the target field, typed by `FieldDefinition.type` (enum → `allowed` only, coordinates range-checked, KNOWN ⇒ value, NOT_APPLICABLE ⇒ null). Each citation's quote must occur (case/whitespace/Unicode-normalised) in the passage shown; ungrounded citations are dropped and claims left without one rejected; citations map to `EvidenceRef` via `bundle.evidence_ref(sid, passage=quote)`. `LLMError(SCHEMA)` → no claims (field returns to discovery/review); other `LLMError`s propagate so the research queue retries the run (successful fields are cache hits). Fields marked `multi_valued` in `config/field_definitions.yaml` (`water_source`, `reservoir_names`) get a prompt line asking for one claim per distinct value. Bump `EXTRACTION_PROMPT_VERSION` (`core/versions.py`) when the prompt or schema changes.

**Cross-cutting**: settings come from `core/config.py::get_settings()` (pydantic-settings, `.env`, cached), including per-city budgets (`MAX_OPENAI_*_TOKENS_PER_CITY` — defined but not enforced anywhere yet — and `MAX_FIRECRAWL_CREDITS_PER_CITY`). Tests that build `Settings` must pass `_env_file=None` (the real `.env` holds a VT key). `services/evidence.py::chunk_document` turns an `AcquiredDocument` into `EvidenceChunk`s.

**Context manager (`context_manager/` package: `manager.py` builds bundles, `store.py` persists them, `service.py` is the graph entry point; import from `water_source_research.context_manager`)**: every LLM call should get its prompt context from `ContextManager().build(ContextTask(purpose, target_fields), city_state, chunks, seen)` (the graph goes through `ContextService`). It is pure/in-memory. Per `ContextPurpose` it prunes targets (already-resolved, derived, nothing-to-resolve → `bundle.skipped_fields`; `bundle.is_empty` means skip the LLM call), adds resolved anchor/`depends_on` values as one-line facts, and then either ranks chunks (EXTRACT: keyword BM25 × source-type prior × city/digit heuristics, per-target seed pass, dedupe, per-source cap, sentence excerpting, token budget) or lists candidate/selected claims (RESOLVE_CONFLICT / VALIDATE: all claims kept, passages shrunk). Sources get `S#` ids; `bundle.evidence_ref("S1")` maps an LLM citation back to an `EvidenceRef`. Callers persist `bundle.consumed` into `seen` so the same (chunk, field) isn't re-sent. The manager never calls a model; LLM response caching belongs in the LLM layer, keyed by `bundle.fingerprint`/`bundle_id`.

**Bundle persistence (`context_manager/store.py`, `db/`)**: `ContextBundleStore(engine).get_or_build(manager, task, state, chunks, seen)` (or `aget_or_build` from async nodes) reuses a stored bundle from the `context_bundles` table when `ContextManager.cache_key(...)` matches. The key covers the policy signature (`RETRIEVAL_POLICY_VERSION`, manager config, token estimator, field definitions) plus only the inputs the build reads: target/anchor/`depends_on` field states, and for EXTRACT the chunk contents and `seen` pairs for the targets. **Bump `RETRIEVAL_POLICY_VERSION` when changing scoring/excerpting/rendering logic** so old bundles aren't reused. Concurrency: a per-key in-process lock builds each bundle once, and the unique `cache_key` constraint settles races across processes (the loser returns the winner's row). `db/` is the repo's first DB code: `db/models.py` (SQLAlchemy 2.x declarative, JSON→JSONB on Postgres) and `db/session.py` (`get_engine()` from `DATABASE_URL`, `init_db()` = `create_all`, schema changes go through Alembic in `migrations/`; `init_db()` = `create_all` for tests/dev). Dialect-specific DDL (the pgvector HNSW index) is declared on the model with `.ddl_if(dialect="postgresql")`, and `db/models.py::include_object_for` keeps Alembic from reporting it as drift on other backends — SQLite-only checks can't catch Postgres drift, so `tests/integration` includes a Postgres drift test). Store tests run on a file-backed SQLite in `tmp_path`. OpenTelemetry (`observability/otel.py`) is intended as the canonical audit layer (run/city/field IDs, provider/model, tokens, latency, cost, confidence, HITL events).

**Procedural memory (`procedures/`)**: reusable *research strategies* learned from validated runs — advisory planning guidance only, never evidence, field state, or an LLM cache. Keep those boundaries: procedure text must never get an `S#` id or satisfy an evidence requirement (`ContextTask.procedure_hints` render only for PLAN/QUERY_GENERATION, in their own section).
- Read path: `graph.plan` → `ProcedureMemory.retrieve(RetrievalRequest)` once per field type with unaccepted fields → SQL metadata filter (ACTIVE, task/field type, water type, `min_workflow_version`, required capabilities) → cosine over survivors only (pgvector `<=>` on Postgres, Python on SQLite) → `RankingPolicy` (Wilson lower bound, EWMA recent success, recency, correction penalty) → ≤`max_results`. `retrieve` never raises (degraded → default strategy). `choose_strategy` drops capabilities not in `available_capabilities()`; `discover` renders query templates into `planned_queries`.
- Write path (async, soft): `finalize` → `RunRecorder` persists `research_runs`/`run_events` and enqueues `distillation_jobs` (key = hash(trajectory_id, `DISTILLER_VERSION`)) → `DistillationWorker`: build trajectory from events → `EligibilityPolicy` → distiller (`procedure_memory.distiller`: `LLMDistiller` by default — the model only picks from per-trajectory enums of observed capabilities/queries/source types and never sees city names, URLs or providers; runs on the configured `LLM_PROVIDER` via the router and falls back to `DeterministicDistiller` when that provider has no credentials) → schema + `check_grounding` + `check_safety` (no URLs/domains/secrets; queries must template to observed, generic-vocabulary searches) → `MergeEvaluator` (same `procedure_key` = metadata + capability plan; structural Jaccard required, embedding cosine only as an extra guard) → CANDIDATE → `LifecyclePolicy` (support runs/cities, correction rate; `require_human_approval` → AWAITING_APPROVAL, approve via `POST /procedures/versions/{id}/approve`).
- Concurrency/idempotency live in the DB: unique `procedure_key`, `(procedure_id, version)`, origin `distillation_key`, usage `(version, run, field)`; partial unique index = one ACTIVE version per procedure; conditional UPDATEs for job claims/transitions; SQL increments for stats. Recipes are immutable; versions change only status/stats/embedding.
- Usage: retrieved → selected → applied → outcome (once) in `procedure_usages`; only applied usages move success/failure stats.
- All thresholds are in `procedures/config.py::ProcedureMemorySettings` (`PROCEDURE_MEMORY__*` env, validated at startup; disabled by default). Version constants are in `core/versions.py`; capabilities (vendor-independent) in `core/capabilities.py`.
- The distiller's version is part of the job key, so `RunRecorder` must be built with the worker's `distiller.version` (`build_procedure_services` does this). Bump `LLM_DISTILLER_VERSION` when the prompt or draft schema changes.
- Tests: `tests/procedure_helpers.py` (FakeEmbedder, `seed_version`, `run_state` event builders); metrics via the `metric_points` fixture.
