# Reports

Curated evaluation reports are in Git; the generated outputs they were computed from stay on
disk next to them, ignored by `.gitignore`, and are listed with their sha256 in each
experiment directory's `manifest.json` (`scripts/report_manifest.py write|check <dir>`).
Research data itself (runs, claims, evidence) lives in Postgres and MinIO, never here.

## Layout for new work

```
eval/<area>/<experiment>/       area: discovery, geo31, tokens, acceptance, ...
  REPORT.md / CHECKPOINT_*.md   tracked: conclusions, absolute counts, run ids, settings basis
  manifest.json                 tracked: generated files with size and sha256, git commit
  before.json, after.json, ...  tracked: small inputs (run-id lists) the scripts take
  *.json, *.jsonl, *.log        ignored: generated by scripts, reproducible from the run ids
  cities/<city-slug>/           per-city outputs: same rules; per-city generated Markdown is
                                named *.generated.md (ignored), aggregates go in REPORT.md
```

Rules:
- Commit curated Markdown, small input/run-id files and manifests; never the reference
  workbook (`resources/`, ignored), raw evaluation JSON, search snapshots or logs.
- Each report states its run ids, code commit, identity basis (approved / draft / name-only)
  and which figures are validated vs provisional.
- Write `manifest.json` once the experiment's outputs are final; `check` before reusing them.
- Superseded outputs stay in their own subfolder with a note (e.g. `discovery/fresh/
  superseded_registry_bug/`); nothing is deleted.
- A new small input file name that must be tracked needs a `!reports/**/<name>` line in
  `.gitignore` (or call it `manifest.json`).
